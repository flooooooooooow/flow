# Community projects

This page is for projects built with Flow by people outside the core Flow repository.

The purpose is practical: help users discover real Flow code, give project authors visibility, and build verifiable evidence of independent language adoption.

## What qualifies

A project should have a public source repository, contain meaningful Flow source rather than only generated fixtures, identify the Flow version or commit it was tested against, and include enough instructions for another person to build or run it.

Forks of the Flow repository, mirrors, benchmark copies, repositories created solely to inflate language statistics, and project-maintainer satellite repositories do not count as independent adoption.

Projects do not need to be production software. Libraries, applications, games, research tools, embedded experiments, DSP projects, numerical work, and substantial learning projects are all welcome.

## Submit a project

Open a **Community project** issue using the repository issue template. Include the repository URL, project author, what it does, the Flow version tested, platform tested, and the shortest reproduction command.

A maintainer can then add a row here. Inclusion is not an endorsement and technically critical or experimental projects are welcome.

## Why this is separate from examples

The repository's `examples/` tree proves implementation breadth. Community projects prove something different: that another person chose Flow for their own problem.

That distinction matters for ecosystem health and for external systems such as GitHub Linguist that explicitly discount usage concentrated under the language owner's repositories.
