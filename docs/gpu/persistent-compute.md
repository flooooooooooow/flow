# Persistent WebGPU execution for Flow compute kernels

`wasm/crossing_assets/gpu-kernel-chain.mjs` and its shipped site copy
`site/wasm-crossings/gpu/gpu-kernel-chain.mjs` extend the existing
`webgpu-host.js` with **real multi-stage WebGPU compute submission**.
The host consumes **WGSL source and reflection generated by Flow**
(`./flow tool tools/gpu/main.flow --crossing-manifest`), rather than
inventing a second GPU kernel syntax.

`runFlowKernelChain(device, {resources, stages, readback})` allocates each
resource once, builds each reflected compute pipeline, dispatches each stage
into the same command buffer, and only maps explicitly requested outputs
after the queue completes. No intermediate tensor must pass through the CPU.

```js
import {getDevice, runFlowKernelChain} from "./webgpu-host.js";

const {device} = await getDevice();
const result = await runFlowKernelChain(device, {
  resources: {
    raw: {length: 784, initial: pixels}, // pixels: Float32Array
    normalized: {length: 784},
    logits: {length: 10}
  },
  stages: [
    {
      descriptor: generatedPreprocessReflection,
      wgsl: generatedPreprocessWgsl,
      bindings: {raw: "raw", norm: "normalized"},
      scalars: {n: 784},
      count: 784
    },
    {
      descriptor: generatedClassifierReflection,
      wgsl: generatedClassifierWgsl,
      bindings: {input: "normalized", output: "logits"},
      scalars: {n: 10},
      count: 10,
      // GEMM may read more than its output dispatch extent. Supply
      // explicit element counts for each bound resource.
      allowNonlinear: true,
      requiredElements: {input: 784, output: 10}
    }
  ],
  readback: ["logits"]
});

console.log(result.execution, result.outputs.logits);
```

The reflection names used above are illustrative; **use the exact buffer
argument names and types emitted by the compiler**. The executor rejects
unknown or aliased bindings, uninitialised tensor reads and unwritten
readbacks, incorrect input shape, over-limit dispatch/workgroup sizes,
invalid shader compilation, malformed uniform params and missing outputs.

For `allowNonlinear: true` (e.g. matrix multiplication where the thread
count and input/weight tensor elements differ), the caller must provide
`requiredElements` for every Flow-reflected buffer name. Every declared
span is checked against its resource's allocated length before any GPU
command is submitted; `allowNonlinear` is not a bypass for bounds
validation.
A successful result has `execution: "webgpu-device"`, not a synthetic
shader-compilation verdict.

Test the host-side contract without a GPU:

```sh
node --test tests/webgpu/kernel-chain.test.mjs
```

On a supported browser, exercise it with actual `navigator.gpu` and the
WGSL + JSON reflection produced by the Flow compiler. A proper vgpu
conformance test also needs captured upstream weights/inputs, absolute error
comparison to a frozen output, and a device-specific result record.

**Scope:** This executes already-generated Flow `@gpu` compute kernels.
It does not automatically translate host Flow control flow into GPU passes,
and does not implement texture/render graph dispatch. The vgpu MNIST and
depth cases run their kernels through this executor on a real adapter:
`flow gpu test --suite vgpu --backend webgpu` (see
[vgpu conformance](vgpu-conformance.md#numerical-cases)).
