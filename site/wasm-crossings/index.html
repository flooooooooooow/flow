WASM crossings

Five things people assume a systems language cannot take to WebAssembly. Flow does all five in runtime C or in its own codegen, so each one is a concrete question with a concrete answer. Every page below states the mechanism, the constraint that made it look impossible, the workaround, and a number measured in a real browser.

crossingwhat actually crossesmeasured in Chrome
1. OS threads pthreads over Web Workers and a shared heap 7.78x on 8 workers, bit-identical results
2. The GPU Flow's own AST to WGSL, dispatched by WebGPU 1,048,576 / 1,048,576 elements agree exactly
3. Sockets BSD sockets mapped onto WebSocket frames 8 / 8 round trips, best rtt 2.20 ms
4. Embedded CPython Flow's embedding ABI routed to Pyodide CPython 3.12.7, 11 / 11 checks
5. The filesystem stdio on MEMFS, IDBFS and preloaded data GIF byte-identical to native, state survives reload

Running them

python3 -m http.server -d site 8000
open http://127.0.0.1:8000/wasm-crossings/

# crossing 3 needs the echo relay running first
python3 scripts/ws_echo_relay.py --port 9505

# rebuilding
./flow wasm examples/wasm/parallel_sum.flow --threads --workers 8
./flow gpu examples/wasm/gpu_vector_add.flow --wgsl
./flow wasm examples/wasm/fs_counter.flow --fs idbfs
python3 wasm/flow_wasm_sockets.py
python3 wasm/flow_wasm_python.py
python3 wasm/flow_wasm_fs.py

Notes that apply to all of them

  • Crossings 1 and 3 need a foreground tab to measure honestly. Chrome clamps timers in a background tab to about 1 Hz, which turned a 3.4 ms round trip into 748 ms with no code change.
  • V8 compiles WASM at a baseline tier first. A workload run once is measuring the baseline compiler; the demos take the best of several passes.
  • Crossing 4 fetches Pyodide from a CDN, so that page needs network. The other four are self-contained.
